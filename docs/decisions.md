## ADR-001: Выбор immutable-дистрибутива хоста

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО

**Кандидаты:** Fedora Silverblue (rpm-ostree/OSTree), openSUSE MicroOS/Aeon
(transactional-update + Btrfs snapshots), Vanilla OS 2 Orchid (ABRoot A/B, Debian sid).

**Критерий (согласован в дебатах, ходы 00–01):** headless-стенд → MicroOS;
ноут остаётся десктопом → Silverblue.

**Решение Антона (18.09):** ноут останется десктопом → **Fedora Silverblue**
(или Kinoite, если Антон выберет KDE; база та же — rpm-ostree + Toolbx/Distrobox).

**Отклонённые:** MicroOS (GNOME-центричный Aeon, выгоден только headless);
Vanilla OS (Apx интересен, но база Debian sid — rolling-сюрпризы, комьюнити меньше).

## ADR-002: Уровень изоляции агентов

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО (консенсус Hermes + DSH)

**Контекст:** контейнеры делят ядро с хостом — это не security sandbox
(dev.to, 01.2026). microVM (Kata/Firecracker/gVisor) дают kernel-boundary,
но дороже в эксплуатации.

**Решение:** шаг 1 — rootless podman-контейнеры (trusted-but-fallible агенты,
защита от случайного ущерба): no-new-privileges=true + cap_drop=ALL по умолчанию,
исключения — явно в манифесте. Шаг 2 — оркестратор в KVM VM, инструменты в контейнерах.
Не прыгаем через ступеньку (DSH, ход 00).

**Последствия:** для недоверенного кода изоляция недостаточна — но такой код на
стенд не попадает (см. ADR-005).

## ADR-003: Политика маунтов

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО (консенсус)

**Кандидаты:** полный $HOME bind (отвергнуто — обнуляет схему) vs точечные маунты.

**Решение:** правило — «маунт только то, что агент умеет пересоздать».
Точечные bind конкретных каталогов (подход jc-dsh работает месяцами: /workspace,
/shared_workspace, персистентное состояние агента — отдельным томом).
Пересоздание контейнера теряет ноль памяти агента.

## ADR-005: Брокерские ключи на стенде (предложение DSH)

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО (консенсус)

**Решение:** брокерских ключей на стенде НЕТ вообще. Только read-only рыночные
данные. Отсутствие ключа не позволяет ордер даже по ошибке — сильнее любых
подтверждений. Торговый контур остаётся на основном хосте.

## ADR-006: Контракт агента — yaml-манифест (предложение DSH)

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО (консенсус)

**Решение:** на каждый агентный образ — манифест контракта (yaml рядом с Dockerfile):
- маунты (ro/rw построчно, источник → цель);
- порты (внутрь/наружу);
- секреты (имена, без значений);
- сетевые зависимости (какие сервисы стенда нужны);
- cgroup-квоты (memory+cpu, без исключений);
- healthcheck и критерий «жив»;
- команда пересоздания с нуля (одна строка).

Спор о начинке агента = diff двух yaml-файлов. Этап 5 (прогон) становится измеримым.

## ADR-007: Общие сервисы — quadlet-юниты на хосте (предложение DSH)

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО (консенсус)

**Решение:** Redis/Qdrant/LightRAG/bus-keeper — отдельные quadlet-юниты на хосте,
НЕ поды, НЕ внутри агентов. Агенты получают сеть (private podman network + порты
на localhost), не тома. Бэкап = список named volumes сервисов. bus-keeper
переносится как образ 1:1.

## ADR-008: bootstrap.sh — весь host-слой кодом (предложение Hermes)

**Дата:** 2026-09-18 · **Статус:** 🆕 ПРЕДЛОЖЕНО (ход 01)

**Контекст:** «переезд между atomic-дистрами дешевле» верно только для контейнеров;
quadlet-юниты, snapshot-политики и podman-сети переносить руками.

**Решение (предложение):** этап 3 включает `bootstrap.sh` в git, поднимающий
стенд с нуля на чистом хосте. Тогда смена дистрибутива = один прогон скрипта.

---

## ADR-004: Секреты в публичном репо

**Дата:** 2026-09-18 · **Статус:** ✅ ПРИНЯТО

**Решение:** репозиторий публичный. Никаких ключей, токенов, паролей, реальных путей
инфраструктуры и внутренних эндпоинтов. Все чувствительные значения — через env /
`.env` (в `.gitignore`). Имена агентов и общая архитектура — ок.
