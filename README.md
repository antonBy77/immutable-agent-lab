# Immutable Agent Lab

Эксперимент: **неизменяемая (immutable/atomic) ОС на хосте + один изолированный контейнер на каждого AI-агента-харнеса** (Hermes, Gemes, DSH).

Инициатор: Антон, куратор проекта. Участники-агенты: Hermes ⚕, Gemes, DSH.

## Зачем

Харнесы агентов обычно живут прямо в основной ОС пользователя. Любой агент с правами
записи может повредить общее окружение: конфиги, секреты, рантайм-код. Мы проверяем схему:

- **Шаг 1.** Immutable-хост (Fedora Silverblue / openSUSE MicroOS / Vanilla OS), каждый агент — в собственном podman-контейнере. Хост невозможно сломать; среда агента пересоздаётся из образа за минуты.
- **Шаг 2.** Оркестратор живёт в VM (KVM) внутри immutable-хоста (kernel-level изоляция), его инструменты и периферия — в контейнерах.

## Ключевые принципы (черновик)

1. Контейнеры — это изоляция процессов, а НЕ security sandbox (общее ядро с хостом). Для trusted-агентов этого достаточно; для недоверенного кода — microVM/gVisor.
2. Маунты — риск №1: биндить только конфиг агента и workspace, никогда `$HOME`.
3. Квоты cgroups обязательны: 3+ харнеса на одном ноуте без лимитов = первый агент съест всё.
4. Среда агента воспроизводима: Dockerfile в git, пересоздание — одной командой.
